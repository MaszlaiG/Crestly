MI EZ AZ APP?
  A Nettli egy személyi vagyonkezelő (arany, részvény, kripto, hitel,
  zálog, előfizetés). Minden felhasználó bejelentkezik, és KIZÁRÓLAG a
  saját adatát látja. Az adat a felhőben, Firestore-ban tárolódik,
  fiókonként egyetlen dokumentumban: vaults/{uid}. NINCS nyilvános
  űrlap — csak bejelentkezett felhasználó ír/olvas.

  Két Firebase-szolgáltatás kell:
    - Authentication → a bejelentkezés (e-mail/jelszó).
    - Firestore     → az adat tárolása a felhőben.

  A weboldal kiszolgálása NEM a Firebase Hostingon történik, hanem
  GitHubon (GitHub Pages). A Firebase-t itt kizárólag adattárolásra
  (Auth + Firestore) használjuk.

  - Ellenőrzés:  firebase projects:list   (látnod kell a nettli-202608-at)

2) AUTHENTICATION (bejelentkezés) — a console-ban
----------------------------------------------------------------------
MIRE VALÓ: ez adja a fiókokat. Enélkül a Firestore-szabály mindent tilt,
mert nincs "bejelentkezett felhasználó" (uid).

LÉPÉSEK:
  Console → Build → Authentication → "Get started"
    → "Sign-in method" fül → "Email/Password" → Enable → Save.

  (Opcionális, ajánlott: Authentication → Settings → "Email enumeration
   protection" bekapcsolása — nehezíti a fiókokkal való visszaélést.)

LÉPÉSEK:

    → Mód:   Production mode       [zárt alap; a szabályt mi adjuk meg]

----------------------------------------------------------------------
4) A DEPLOY-FÁJLOK (már a mappában vannak)
----------------------------------------------------------------------
Ezek a fájlok már készen a Nettli mappájában — nem kell "firebase init":

  firebase.json          → a Firestore beállítása (szabály + index fájl).
  .firebaserc            → rögzíti a projektet: nettli-202608.
  firestore.rules        → a biztonsági szabályok (ld. 5. pont).
  firestore.indexes.json → (üres) index-fájl.


----------------------------------------------------------------------
5) FIRESTORE SZABÁLYOK — MAGYARÁZAT (firestore.rules)
----------------------------------------------------------------------
Ez a VÉDELEM MAGJA. A szabály:

    match /vaults/{uid} {
      allow read, write: if request.auth != null && request.auth.uid == uid;
    }

Jelentése:
  - request.auth != null  → csak BEJELENTKEZETT felhasználó.
  - request.auth.uid == uid → és KIZÁRÓLAG a SAJÁT dokumentumát
    (vaults/{a-saját-uid-ja}) írhatja/olvashatja.
  → Egyik fiók sem látja a másik pénzügyi adatát.

A szabály a "firebase deploy --only firestore:rules"-zal automatikusan
felkerül (a firebase.json tartalmazza a firestore blokkot) — nem kell a
console-ban kézzel bemásolni.


----------------------------------------------------------------------
6) A FIRESTORE-SZABÁLY FELTÖLTÉSE
----------------------------------------------------------------------
A Nettli mappájában (a weboldal kiszolgálása GitHubon van, ide csak a
Firestore-szabály/index kerül fel):

    cd "<a Nettli mappa útvonala>"
    firebase deploy --only firestore:rules

  Ez felteszi a FIRESTORE-SZABÁLYT. Minden szabálymódosítás után futtasd
  újra. (A firestore.indexes.json is így megy fel, ha bővül.)


----------------------------------------------------------------------
7) A WEBOLDAL KÖZZÉTÉTELE (GitHub)
----------------------------------------------------------------------
- A statikus fájlokat (index.html, css/, js/ stb.) töltsd fel a GitHub
  repóba, és a GitHub Pages szolgálja ki (Settings → Pages).
- Nyisd meg az élő oldalt → REGISZTRÁLJ egy fiókot (e-mail + jelszó) →
  az adat a Firestore → Data fülön a vaults/{uid} alatt megjelenik.
- FONTOS: a GitHub Pages domainjét (pl. <felhasznalo>.github.io) vedd fel
  az engedélyezett domainek közé: Authentication → Settings → Authorized
  domains — különben a bejelentkezés nem működik az élő oldalon.
- Új fiók ÜRESEN indul (nincs mintaadat).


----------------------------------------------------------------------
8) (OPCIONÁLIS) EGYEDI DOMAIN
----------------------------------------------------------------------
Egyedi domaint a GitHub Pages-nél állíts be (repo → Settings → Pages →
Custom domain), és állítsd be a DNS-t a domainszolgáltatónál. Utána vedd
fel az új domaint: Authentication → Settings → Authorized domains.


----------------------------------------------------------------------
9) BIZTONSÁG DIÓHÉJBAN
----------------------------------------------------------------------
- HTTPS: a GitHub Pages adja automatikusan.
- Auth + Rules: a bejelentkezés + a uid-re zárt szabály védi az adatot.
- apiKey: a kódban lévő apiKey NEM titok (publikus azonosító); a védelmet
  az Auth + a Firestore-szabályok adják.
- App Check (bot-védelem): a Nettlinél kevésbé kritikus, mert NINCS
  nyilvános írás (csak bejelentkezett user ír). Később bekapcsolható.
- Backup: a Fiók → Export data funkcióval bármikor JSON mentés.
